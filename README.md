# ArchitecturePlanner

[在线规划台](https://thu-mem.github.io/ArchitecturePlanner/) · [React Flow](https://reactflow.dev/)

基于 AI-MEM 架构的可编辑规划台，支持模块、技术组件、依赖与分工。模块和组件各支持一位主 owner、多位协作 owner。Owner 仅是规划信息，不授予账号或权限。

## 使用与发布

1. 页面默认展示已发布规划；如需继续浏览器中的修改，点击「恢复本地草稿」。
2. 编辑模块或组件后「应用」，可导入、导出 JSON 备份。此时修改仍只在当前浏览器。
3. 点击「提交到 GitHub」→「复制并前往 GitHub」，在原生编辑器全选粘贴，再 Commit 或提 PR。无需向规划台提供 Token。
4. 变更进入主分支并通过检查后，Pages 自动发布；审核、权限与冲突处理由 GitHub 和维护者负责。

复制失败时可手动复制页面中的 JSON 或导出文件，不会自动跳转。复制和打开 GitHub 不代表已提交，返回后仍可恢复草稿。

**规划与分工会进入公开仓库，导出文件也包含人员信息。只填写获授权公开的昵称与规划内容，不要加入凭据、邮箱或其他个人信息。**

## 数据与边界

[规划 JSON](src/seed-plan.json) 是正式数据源，分工与账号映射由维护者人工核对更新。账号映射仍待确认；空白认领保持未分配，不推断协作或组件负责人。

箭头表示上游 → 下游，保留依赖反馈环。业务架构默认展示全部依赖，由 ELK 按拓扑自动排列模块、减少交叉并绕开节点；相对选中模块，蓝线表示上游、橙线表示下游，其他依赖为灰线。可取消「全部连线」聚焦当前模块、缩放查看或「重新布局」。自动布局仅改变当前视图，不写入草稿；手动拖动后保存当前模块坐标，拖动相关的线改用动态折线。模块详情支持双向跳转。

成员和分工使用 DiceBear 首字母头像，在浏览器本地生成，不向外部头像服务发送信息，也不改变规划 JSON。已映射账号使用获授权的姓名拼音缩写；公开映射仅保存 GitHub 昵称与不重复的两字母缩写，不包含真实姓名、完整拼音或源文档链接。未映射的成员沿用显示昵称生成头像。
选中画布模块后，直接上游卡片显示深蓝色光晕，直接下游显示淡黄色光晕，兼具两种关系的反馈模块显示双色光晕；其余卡片与无关连线淡化，但仍可点击。工具栏图例与「全部连线」同排，窄屏可横向滚动。
再次点击已选卡片或点击画布空白处可取消选中，恢复全部卡片与连线的正常显示；键盘聚焦卡片后用 Enter / 空格切换选中，Esc 取消选中。未选中时不限制为当前模块连线。
团队成员列表中，已确认的 GitHub 昵称可点击并在新标签页打开主页；手动添加的普通姓名不推断账号。

左上角依次为「业务架构」「技术架构」「分工清单」「技术组件」「团队成员」「原始架构」。业务架构选中模块时，右侧当前 owner、直接上游 owner、直接下游 owner 同步显示青色、深蓝色、淡黄色提示；兼具关系的人员保留全部标签，其余人员淡化。高亮不勾选协作 owner、不修改分工；依赖按钮同时展示对应模块的 owner，可留在业务画布继续追踪。

「技术架构」复用原项目现状页面、React Flow 与共享 ELK 布局／连线，覆盖 Kubernetes 基础设施、入口、身份、服务、存储和独立业务。支持全部组件／运行现场／源码与待接入筛选、缩放、适应全图与双向关系导航；此图只读，不写入业务规划 JSON。

技术事实依据 AI-MEM 的 `server/deploy`、`server/services` 与 **2026-11-02 18:40 UTC+08:00 的实际 SSH 只读核对**。现场为单节点 Kubernetes，19 个 Pod 中 18 Running、1 Pending；APISIX、网络/DNS、证书控制器、持久卷、Keycloak 与 PostgreSQL 已就绪。MEM-AI 因 `ErrImageNeverPull` 未启动，Service 无就绪端点，当前配置 SQLite 与独立 PVC；模板中的 MySQL／Redis 不能画成线上依赖。hub-api、事件服务、Redis、MinIO、ClickHouse、MCP、案例应用与 LLMWiki 本次集群未见，不推断其他主机的状态。实线表示现场资源／配置关系，虚线表示源码／模板，点线表示待接入，**均不等于端到端业务验收**。

快照仅公开脱敏职责与状态，不含服务器地址、私有域名、Secret、环境变量值、人员实名或原始运维输出；不是实时监控，不自动改变规划状态。原始架构仍只读，规划台本身不接入 SSO，也不连接服务器、数据库或 Kubernetes API。

部署可通过 `VITE_GITHUB_PARTICIPANTS` 补充获授权公开的 GitHub 昵称，配置格式见[参与者合并逻辑](src/participants.ts)。按稳定账号 ID 合并，不重置已有分工；配置会进入公开页面，不能用于保存秘密。
